# خطة التطوير الشاملة لمحرك وسائط ذاري ماكس (Dhari Max) – المراجعة الثانية

تحديث معماري شامل لمحرك الاستخراج والتحميل في تطبيق **ذاري ماكس – Dhari Max** استجابةً للملاحظات والمتطلبات التفصيلية، لضمان تحميل سليم وتشغيل حقيقي لملفات الفيديو والصوت من مختلف المنصات (يوتيوب، فيسبوك، روابط مباشرة) ومنع أي فشل أو حفظ وهمي للملفات.

---

## 1. القرارات الهندسية للمتطلبات الإضافية

### أ) دراسة وتنفيذ محرك yt-dlp ومزودات الاستخراج
- **دراسة yt-dlp ضمن بيئة أندرويد**:
  - يتطلب تشغيل ثنائيات `yt-dlp` بايثون حزمة بايثون كاملة ومترجمة للمنصة (`cpython-android`) بحجم يتجاوز 60 ميغابايت ومعقد البناء.
  - **الحل الأفضل والأكثر موثوقية**: بناء مزود `YtDlpApiExtractorProvider` يتكامل مع واجهات yt-dlp REST APIs ومحركات الاستخراج المعيارية المتوافقة مع yt-dlp (مثل واجهات Cobalt و Piped و Invidious)، بالإضافة إلى إتاحة خيار في الإعدادات لإدخال رابط خادم yt-dlp خاص (Custom Server URL) للمستخدمين المتقدمين.
- **واجهة موحدة `MediaExtractorProvider`**:
  - فصل كل منصة في فئة مستقلة:
    - `YouTubeExtractorProvider`: مخصص لروابط يوتيوب بأنواعها.
    - `FacebookExtractorProvider`: مخصص لروابط فيسبوك.
    - `DirectMediaExtractorProvider`: مخصص للملفات المباشرة.
    - `YtDlpApiExtractorProvider`: محرك احتياطي يستند لبروتوكول yt-dlp.
  - واجهة تسجيل مركزية `ExtractorRegistry` تسمح بإضافة أي منصة جديدة مستقبلاً دون المساس بـ `DownloadManager`.

### ب) فحص ديناميكي للخوادم (Dynamic Instance Health Checker)
- عدم الاعتماد على قائمة خوادم ثابتة؛ فحص صحة الخادم عبر طلب خفيف (`/api/v1/stats` أو HEAD request بمهلة قصيرة 2.5 ثانية).
- استبعاد الخوادم المحجوبة أو التي تعيد خطأ 429 (Rate Limited)، واختيار أسرع خادم مستجيب تلقائياً.

### ج) دمج مسارات الفيديو والصوت المنفصلة (Adaptive Streams Muxing)
- دعم استخراج الفيديو والصوت المنفصلين عبر نظام **Android MediaMuxer** المدمج في نظام أندرويد (`android.media.MediaMuxer` و `android.media.MediaExtractor`).
- يقوم بدمج مسار فيديو MP4 ومسار صوت AAC/M4A في ملف MP4 موحد بدون الحاجة إلى مكتبات خارجية ثقيلة، وبأقصى سرعة معالجة على جميع إصدارات أندرويد.
- كما يتم تفضيل صيغ الدفق المدمجة (Muxed Progressive Streams) مثل 720p و 360p للتحميل الفوري المباشر.

### د) التحقق الثلاثي الصارم من سلامة الملفات (Triple-Tier File Validation)
عدم الاكتفاء بفحص الترويسات وحده:
1. **فحص Content-Type**: رفض أي استجابة تحتوي على `text/*` أو `text/html` أو `application/json`.
2. **فحص الـ Magic Bytes**:
   - لملفات MP4: التحقق من وجود توقيع `ftyp` (بايتات: `0x66 0x74 0x79 0x70`) في بداية الملف أو وجود صناديق `moov` / `mdat`.
   - لملفات MP3: التحقق من علامة `ID3` أو مزامنة إطارات MPEG (`0xFF 0xFB / 0xFA / 0xF3`).
   - لملفات M4A: التحقق من توافق `M4A ` في ترويسة ftyp.
3. **فحص مشغل النظام (Android MediaExtractor)**:
   - تمرير الملف بعد اكتماله إلى `android.media.MediaExtractor` للتأكد من احتوائه على مسارات وسائط صالحة (`trackCount > 0`). وإذا فشل، يُصنف التحميل كفاشل مع توضيح السبب ولا يوضع في المعرض كملف صالح.

### هـ) استكمال التحميل الآمن مع HTTP 206
- إرسال ترويسة `Range: bytes=X-`.
- فحص استجابة الخادم:
  - إذا كانت `HTTP 206 Partial Content` وترويسة `Content-Range` متوافقة: يتم إلحاق البيانات من موقع التوقف.
  - إذا أعاد الخادم `HTTP 200 OK` (تجاهل التجزئة): يتم تصفير الملف المؤقت وبدء التحميل من البايت 0 لتجنب تكرار البيانات أو تلف الملف.

## 3. خطة العمل المباشرة للتنفيذ (Execution Steps)

1. **بناء معمارية الاستخراج الموحدة (`MediaExtractorProvider`)**:
   - إنشاء واجهة `MediaExtractorProvider` مع دوال التحقق والاستخراج وتحديد الأولوية.
   - إنشاء `YouTubeExtractorProvider` مع استخراج معرفات الفيديو وفحص خوادم البث الصالحة وتجاوز الخوادم المعطلة.
   - إنشاء `FacebookExtractorProvider` و `DirectMediaExtractorProvider`.
   - إنشاء `ExtractorRegistry` كطبقة موحدة تُسهل إضافة أي منصات إضافية.
2. **تطوير محرك فحص سلامة الملفات (`MediaValidator`)**:
   - التحقق من ترويسات الاستجابة ونوع MIME.
   - فحص Magic Bytes الحقيقية لكل نوع ملف (MP4, MP3, M4A).
   - استخدام `android.media.MediaExtractor` للتأكد من قدرة أندرويد على قراءة المسارات.
3. **تطوير دمج المسارات (`MediaMuxerHelper`)**:
   - دمج مسارات الفيديو والصوت المنفصلة باستخدام `MediaMuxer` عند الحاجة.
4. **تطوير `DownloadManager` مع دعم Range الآمن**:
   - معالجة `206 Partial Content` مقابل `200 OK`.
   - التحقق الثلاثي قبل اعتماد اكتمال التحميل.
5. **إضافة اختبارات شاملة في `ExampleUnitTest.kt`**:
   - اختبار مزودات الاستخراج وتحديد الروابط.
   - اختبار فحص Magic Bytes ورفض صفحات HTML.
   - اختبار محاكاة Range headers وتحديد سلوك الاستكمال الآمن.
6. **بناء وتثبيت واختبار التطبيق**:
   - تنفيذ `compile_applet` وتشغيل الاختبارات للتأكد من نجاح العملية بالكامل.
